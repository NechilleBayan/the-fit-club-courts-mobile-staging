# Decision log: Admin console integration

Append-only. Newest last. One row per decision, and a decision is anything that
removed, merged, renamed, reassigned, or overrode something that existed before.

The test this log has to pass: Someone reading only this file can find anything
that disappeared, and can tell a deliberate call from an accident.

Where the prompt was silent and judgement was exercised, the row says so and
names the alternative that was rejected.

| # | Phase | Decision | What changed | Why | Reversible? |
|---|---|---|---|---|---|
| 1 | 0 | Baseline is commit `f46784e`, not `60399fb` | Branch `admin-console-integration` cut from `main` at `60399fb`. The `admin/` folder was untracked on `main`, so it was committed verbatim as `f46784e` before any edits. | A 27-file folder that git has never seen produces no diff. Every later change to `admin/` would have arrived as an undifferentiated block of new files, which makes the branch unreviewable. `f46784e` contains zero edits, so it is a true baseline. | Yes. `git diff f46784e -- admin/` is the whole of this branch's admin work. |

Rejected alternative: Commit them and accept the noise. | Yes. Delete the ignore line and `git add .baseline`. |

| 5 | 0 | Prompt fact corrected: The staff shell does have desktop navigation | No code change. Recorded so Phase 2 is not built on a wrong premise. | The prompt states the staff shell has no desktop navigation above 1024 and that a Front Desk user gets the customer header as their only nav. Neither is true. `render()` populates `#bar-nav` and `#tabhost` from the same `STAFF_TABS` array on the staff branch, so the header carries Today, Scan, Walk-in, Open Play, and Exceptions with `aria-current` on the live one, and the 1280 baseline of `/staff/today` shows it. The Phase 2 sidebar therefore replaces a working, deliberately chosen desktop nav rather than filling a hole, which is a stronger claim than the prompt assumed and is settled in row 6. | n/a |
| 6 | 1 | The persisted key is `tfc-staging`, holding exactly six scalars | `{ surface, scenario, connectivity, capacity, clockOffset, theme }`, one JSON object, validated on every read. `S.orders` is not in it and never will be. | An order graph carries absolute hold deadlines, generated identifiers, and a share token per pass, and about thirty functions in `index.html` mutate it. Moving it across a document boundary means freezing all of that into a wire format and keeping two renderers honest about it forever. The console gets a scenario key and draws its own sample instead. | Yes. One file, one key. |
| 7 | 1 | Theme defaults to `null`, not to a colour | `getTheme()` returns `null` until somebody chooses. Each build passes its own fallback to `applyTheme()`: The customer build passes `dark`, the console passes `system`. | Picking a single global default would have repainted one of the two builds for a reader who never asked. The customer build ships `<html data-theme="dark">`; the console ships System selected and renders light. Either choice regresses 27 or 25 baseline screenshots on day one. `null` means "nobody has chosen, keep your own default", so both baselines are preserved and an explicit choice still crosses. Rejected alternative: Default everything to dark. | Yes. |
| 8 | 1 | The old `tfc-theme` key is migrated and then deleted | First read adopts a `dark`/`light` value from `tfc-theme`, writes it into `tfc-staging`, and removes the old key. | Keeping both would be two sources of truth for one setting, which is the exact thing this phase exists to remove. Migrating preserves the reader's current preference, which is the other half of the requirement. Rejected alternative: Keep mirroring writes to `tfc-theme` for backward compatibility. Note the consequence: `claude-version-index.html`, the superseded snapshot, still reads `tfc-theme` and will fall back to its own pinned default. It is a frozen snapshot and out of scope. | Yes, but the old key is gone once a browser has loaded the new build. |
| 9 | 1 | Behaviour change: Reset all state now clears the theme | It previously did not. The comment in `index.html` called the theme "the one thing in this build that outlives a refresh". | Checkpoint 1 asks that Reset return both surfaces to default, and a reset that leaves the console painted in a choice made twenty minutes ago in the other build is not a reset. The old comment has been rewritten to say the new rule rather than left to contradict the code. | Yes. Exclude `theme` from `STAGING.reset()`. |
| 10 | 1 | The armed scenario is remembered but not replayed in the customer build | `loadScenario()` writes the key. Boot restores surface, connectivity, capacity, and clock offset, but does not re-run the seeding. The harness marks the armed scenario with `aria-pressed` so it is still visible. | Replaying on load would mint a fresh order with a new identifier and a new hold deadline while the address bar still pointed at the order the previous run created, which is a 404 dressed as a feature. Dials persist; bookings do not. Rejected alternative: Re-seed on boot and rewrite the hash. | Yes. |
| 11 | 1 | Deviation from the prompt: The bridge is a `<script>` tag in each admin page's head, not a dynamic load from `admin.js` | 27 admin pages gained `<script src="../staging-state.js" data-default-theme="system">` in the head, ahead of the stylesheet. `admin.js` subscribes but does not load the file. | The prompt said to load it from `admin.js`. `admin.js` is at the foot of the body, so anything it loads runs after the first paint, and the first thing this file does is settle the theme. Loading it there is a guaranteed flash of the wrong theme on every one of 27 pages. The default is declared on the tag itself so each document names its own fallback in one place. | Yes. |
| 12 | 1 | `index.html` is no longer a single self-contained document | It now loads one external script, `staging-state.js`, from its own origin. | It already loaded 18 carousel JPEGs and ten font files, so this is not the first request, but it is the first script. The alternative was pasting the same 250 lines into both builds, which is two sources of truth for the thing whose whole purpose is to be one. Consequence: Opening `index.html` over `file://` now depends on the browser allowing a sibling script and an origin-null localStorage. The project already specifies a local server. | Yes. |
| 13 | 1 | `ACTIONS.resetall` split into `resetRuntime()` plus `STAGING.reset()` | `loadScenario()` now calls `resetRuntime()` rather than `ACTIONS.resetall()`. | Loading a scenario has to start from a clean runtime but must not throw away the reader's theme, which now lives in the persisted half. Only the button that says it resets everything clears the key. Side effect: `loadScenario()` no longer fires an intermediate `go("/")`. That was invisible, because `go()` sets `location.hash` and every scenario navigates again before the resulting `hashchange` fires, so only the final route was ever rendered. | Yes. |
| 14 | 1 | `subscribe()` callbacks receive a third argument, `origin` | `"local"` for a change made in this document, `"remote"` for one that arrived by storage event. | Without it, a control that has already updated its own runtime and rendered gets told to do it again on its own echo, so every tap renders twice. The prompt specified a change-subscription hook and left the shape open. Also added: Setters for connectivity, capacity, and clock offset, which the prompt listed only as getters, because the harness has to write them. | Yes. |
| 15 | 1 | Copy rewritten in three places, because it had become untrue | `openDemo()`'s intro, `scrDemo()`'s lede plus a new "What survives a refresh" section, and `admin/settings.html`'s "nothing is saved" sandbox note. | All three promised that nothing persisted. The theme picker in Settings, in particular, sat under a note saying nothing is saved while being the one control that now genuinely saves. The sandbox-honesty rule makes fixing this mandatory rather than optional. | Yes. |
| 16 | 1 | Verification harness: Pixel diff with a stated noise floor, not byte equality | Screenshots freeze the clock, force every declared font face to load, decode every image, and disable animation and transition before capture. Comparison is `pixelmatch`, reporting differing pixel counts. | Byte equality produced 11 false positives out of 104 against an unchanged tree. Residual noise floor after all of that: `desktop/app__court` and `desktop/app__event` still flip height occasionally ON THE BASELINE TREE, by 1px and 23px. Both were confirmed to flake on `f46784e` with no changes applied, so neither is attributable to this branch. | n/a |
